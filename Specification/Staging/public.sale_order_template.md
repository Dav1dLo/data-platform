# sale_order_template

## Source system
This table originates from Odoo ERP, as evidenced by the characteristic naming conventions such as `create_uid`, `write_uid`, `write_date`, and the use of `JSONB` for configuration fields like `journal_id`. The structure is typical of Odoo's internal ORM-mapped tables for managing reusable sales quotation templates.

## Functional process 
This table supports the "Quote-to-Cash" business process by storing predefined templates for sales orders. These templates allow users to standardize terms, payment requirements, and automated email triggers for recurring sales scenarios, ensuring consistency across the sales organization.

## Description
One row in this table represents a single sales order template configuration, defining default behaviors like signature requirements, payment terms, and associated email templates. As a staging table, it serves as a raw, direct copy of the Odoo database record, intended for downstream transformation into analytical models.

## Caveats for downstream consumers

- **Timestamps:** Timestamps are stored in UTC as per standard Odoo behavior.
- **Soft Deletes:** The `active` column acts as a soft-delete flag; ensure queries filter by `active = TRUE` unless historical analysis is required.
- **JSONB Data:** The `note` and `journal_id` columns contain semi-structured data; use PostgreSQL `->>` or `->` operators to extract specific values.
- **Sensitive Data:** No direct PII is present, but `create_uid` and `write_uid` link to internal employee identities.
