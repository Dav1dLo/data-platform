# pos_order

## Source system
This table originates from Odoo ERP, specifically the Point of Sale (POS) module. The naming conventions (e.g., `pos_reference`, `pricelist_id`, `fiscal_position_id`, `account_move`) and the use of `create_uid`/`write_uid` audit columns are characteristic of Odoo's internal data structure.

## Functional process 
This table supports the retail sales and checkout process. It captures the header-level details of point-of-sale transactions, including financial totals, customer identification, session tracking, and payment status, which are essential for downstream revenue reporting and inventory reconciliation.

## Description
One row in this table represents a single point-of-sale order header, capturing the financial summary and metadata for a transaction completed at a POS terminal. It serves as a raw landed copy of the Odoo `pos.order` model within the staging layer, providing the primary record for sales activity before any business logic transformations.

## Caveats for downstream consumers

- **PII:** The `email` and `mobile` columns contain personally identifiable information and should be masked or restricted based on data governance policies.
- **Timestamps:** Timestamps (`date_order`, `create_date`, `write_date`) are typically stored in UTC in Odoo; verify against local server settings if timezone conversion is required.
- **Soft Deletes:** Odoo generally does not use soft-delete flags; records are usually permanent, though the `state` column should be used to filter out 'draft' or 'cancelled' orders.
- **Currency:** Financial columns (`amount_total`, `amount_tax`, etc.) are stored as `NUMERIC` to maintain precision; ensure calculations handle these as exact decimals rather than floats.
