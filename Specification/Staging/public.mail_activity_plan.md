# mail_activity_plan

## Source system
This table originates from an Odoo ERP system. The naming convention (e.g., `res_model`, `create_uid`, `write_uid`, `res_model_id`) and the use of sequence-based primary keys are characteristic of the Odoo framework's internal data structure for managing automated activity workflows.

## Functional process 
This table supports the "Activity Planning" business process, which defines templates or plans for automated tasks (activities) associated with specific business objects (e.g., CRM leads, sales orders). It allows users to pre-configure sequences of activities to be triggered automatically based on the `res_model` defined in the plan.

## Description
One row in this table represents a single activity plan template used to standardize follow-up tasks across the organization. This is a raw landed copy of the Odoo `mail.activity.plan` model, serving as the staging layer entity for downstream activity orchestration.

## Caveats for downstream consumers

- **Timestamps:** Timestamps are stored in UTC as per standard Odoo configuration.
- **Soft Deletes:** The `active` column acts as a soft-delete flag; queries should filter by `WHERE active = TRUE` to retrieve only currently valid plans.
- **Data Integrity:** As a staging table, this may contain orphaned references if the source system's referential integrity is not strictly enforced at the database level.
- **Sensitive Data:** Contains user IDs (`create_uid`, `write_uid`) which may need to be joined against a user directory to resolve names.
