# account_analytic_account

## Source system
This table originates from Odoo ERP, as evidenced by the naming convention `account_analytic_account`, the use of `JSONB` for multi-language names, and standard Odoo audit columns like `create_uid`, `write_uid`, `create_date`, and `write_date`.

## Functional process 
This table supports the financial and project accounting process by managing analytic accounts. These accounts are used to track costs and revenues across different dimensions (such as projects, departments, or cost centers) independent of the formal chart of accounts, linking them to specific partners and companies.

## Description
One row in this table represents a single analytic account used for cost center or project tracking. It serves as a raw landed copy of the Odoo analytic account entity, capturing the configuration, hierarchy, and audit metadata for each account.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| id | INTEGER | false | Surrogate primary key | Sequence-generated by Odoo. |
| plan_id | INTEGER | false | Analytic plan identifier | Links to the analytic plan structure. |
| root_plan_id | INTEGER | true | Root analytic plan identifier | Used for hierarchical plan structures. |
| company_id | INTEGER | true | Company identifier | Links to the owning company. |
| partner_id | INTEGER | true | Partner identifier | Links to the associated customer or vendor. |
| create_uid | INTEGER | true | Creator user ID | ID of the user who created the record. |
| write_uid | INTEGER | true | Last modifier user ID | ID of the user who last updated the record. |
| code | VARCHAR | true | Analytic account code | Short alphanumeric reference code. |
| name | JSONB | false | Account name | Multi-language name stored as a JSON object. |
| active | BOOLEAN | true | Active status | Soft-delete flag; false indicates the account is archived. |
| create_date | TIMESTAMP | true | Creation timestamp | Recorded in UTC by the Odoo application. |
| write_date | TIMESTAMP | true | Last update timestamp | Recorded in UTC by the Odoo application. |

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):** 
    - `company_id` → `res_company.id` (Standard Odoo link to company).
    - `partner_id` → `res_partner.id` (Standard Odoo link to business partner).
    - `create_uid` / `write_uid` → `res_users.id` (Standard Odoo link to system users).
- **Natural keys (inferred):** 
    - `code` (Often used as the unique business key for analytic accounts).

## Caveats for downstream consumers

- The `name` column is stored as `JSONB`; you will need to extract the relevant language key (e.g., `name->>'en_US'`) to use it in reports.
- Timestamps (`create_date`, `write_date`) are stored in UTC.
- The `active` column acts as a soft-delete flag; ensure your queries filter by `active = true` if you only want current, operational accounts.
- This is a staging table; expect raw data types and potential duplicates if the ingestion process does not handle Odoo's incremental sync logic perfectly.
