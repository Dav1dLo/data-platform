# res_country

## Source system
This table originates from Odoo ERP, as evidenced by the naming convention (`res_country`), the use of `JSONB` for localized fields (`name`, `vat_label`), and the specific audit columns (`create_uid`, `write_uid`, `create_date`, `write_date`) characteristic of the Odoo ORM.

## Functional process 
This table supports the global configuration and master data management process for geographical entities. It defines country-specific business rules, such as whether a state or zip code is required for address validation, and provides localized display names and VAT labels for international operations.

## Description
One row represents a single country entity defined within the ERP system. It serves as a raw landing copy of the master country configuration, providing the necessary metadata for address formatting, international dialing codes, and currency associations.

## Caveats for downstream consumers

- **Localization:** The `name` and `vat_label` columns are `JSONB`. You will need to extract the specific language key (e.g., `name->>'en_US'`) to use these in reports.
- **Timestamps:** Timestamps are stored in UTC as per standard Odoo behavior.
- **Data Integrity:** This is a reference table; while `code` is the natural key, ensure joins are performed on `id` where possible to maintain consistency with other Odoo-linked tables.
- **No Soft Delete:** This table typically does not implement soft deletes; records are generally permanent master data.
